# Sample runs (fake data for UI work)

Generated by `python fixtures/make_sample_run.py` into `fixtures/sample_run/`.
Everything is marked `"fixture": true`. Chips and kiln positions are real SentinelKilnDB tiles
from Kasur; states, confidences, CIDs, model hash and risk scores are made up.

```
sample_run/
  index.json                      runs list: runId, sceneDate, recordCount, merkleRoot, file paths
  chips/<h3>.png                  128x128 RGB chip per kiln (chipSha256 in records matches)
  kasur-fixture-2025-01/          run 1: 20 kilns, all state NEW (first sighting, prevState null)
    manifest.json                 schema: schemas/manifest.schema.json
    proofs.json                   per kiln: recordHash, leaf, proof[]; plus root
  kasur-fixture-2025-12/          run 2: 21 kilns, covers every UI case:
                                    2 CONVERTED (FCBK -> Zigzag)
                                    1 NOT_SEEN
                                    3 NON_ZIGZAG with thermal anomaly + inBanWindow (high risk)
                                    1 brand-new kiln (NEW)
                                    the rest NON_ZIGZAG / ZIGZAG
```

Notes for Person B
- Coordinates are integers: `centroid_e6` / `polygon_e6` are `[lon, lat] x 1e6`. Divide by 1e6 for the map.
- `confidenceBp` is basis points (8731 = 87.31%). `thermalDtCk` is centi-kelvin (315 = 3.15 K) or null.
- `chipCID` values are `FIXTURE-...` placeholders, not real IPFS CIDs. Serve chips from `chips/<h3>.png`.
- A kiln keeps the same `kilnId` across runs; use it to build the timeline on the kiln page.
- `proofs.json` is what `GET /proof/{runId}/{kilnId}` should return (plus `batchId` once on-chain).
- Hashing rules: see `pipeline/merkle.py` and `CLAUDE.md`. `web/lib/merkle.ts` must reproduce the
  same `recordHash`, `leaf` and `root` for these files (use them as the parity test vectors).
